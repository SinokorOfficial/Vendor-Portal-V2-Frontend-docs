    트러블슈팅¶

    프론트(Vite·Vue 3) 개발/이관 중 드러나 해결한 문제들을 모은다. 각 항목은 증상 → 원인 → 해결 → 근거(파일) 형식. 새 문제는 영역별 섹션에 같은 형식으로 추가한다.

    1. 리포트 HTML 뷰어 (CmsHtmlReportPopup)¶

    DevExpress(.NET 리포트 서버, Windows 전용 → Azure Linux 이전 불가) 의존을 없애려고 리포트를 자체 HTML/CSS 뷰어로 이식하며 겪은 문제들. 공통 셸 = src/pages/cms/popup/CmsHtmlReportPopup/index.vue, 리포트별 레이아웃 = CmsHtmlReportPopup/reports/<Report>.vue.

    1.1 항목이 많아지면 행이 페이지 경계에서 잘리거나 빈 영역으로 흘러넘침¶

    • 증상: 견적 상세처럼 라인아이템이 많은 리포트에서, 페이지 경계에 걸린 행이 반쯤 잘리거나 행들이 회색 캔버스 배경으로 흘러넘쳐 레이아웃이 깨짐.
    • 원인: "페이지당 고정 행수(rowsPerPage)"로 분할했는데, 라인아이템이 코드+의미를 위아래로 쌓는 구조라 행 높이가 제각각. 키 큰 행이 몰린 페이지가 A4 가용 높이를 초과.
    • 해결: 고정 행수 → 실제 높이 누적 분할. 측정 패스에서 전체 행을 한 페이지에 렌더해 각 tr 실제 높이를 재고, 누적 높이가 가용 높이(297−24mm − 헤더 − 푸터)를 넘기 직전까지만 한 페이지에 담는다(computePages). 인쇄 안전장치로 tr { page-break-inside: avoid }.
    • 근거: CmsHtmlReportPopup/index.vue computePages() / pages computed.

    1.2 마지막(합계) 페이지에 큰 빈 공간이 생기고 페이지가 밀림¶

    • 증상: 짧은 리포트에서 푸터 위로 큰 여백, 또는 합계 블록이 다음 페이지로 밀림.
    • 원인: 푸터 margin-top: auto 가 푸터를 페이지 바닥으로 밀어 큰 갭 생성 + 자동 분할 측정이 root.bottom 기준이라 푸터 아래 빈 공간까지 합계 블록 높이로 오측정.
    • 해결: 리포트 컴포넌트 푸터의 margin-top: auto 제거(내용 바로 뒤 배치) + 합계 블록 높이를 footer.top − tbody.bottom 으로 측정.
    • 근거: reports/*.vue 의 .*-foot, computePages() 의 grandPx.

    1.3 인쇄 시 배경색 누락·머리글/바닥글·빈 페이지¶

    • 증상: 인쇄/PDF에서 회색 표 헤더·합계행 배경이 빠지고, 좌하단에 URL·날짜 자동 바닥글, "한 장 걸러 빈 페이지".
    • 원인: 브라우저 인쇄 기본 동작(배경 생략·여백에 머리글/바닥글·min-height:297mm 초과분 흘림·이중 page-break).
    • 해결: 인쇄 iframe CSS — * { print-color-adjust: exact }, @page { size:A4; margin:0 } + 여백은 .hr-page padding, 인쇄 시 height:auto/min-height:0, page-break는 page-break-after 하나만.
    • 근거: CmsHtmlReportPopup/index.vue nativePrint() 주입 스타일.

    1.4 GRAND TOTAL/합계가 마지막 페이지에서만 비거나 0¶

    • 증상: 목록/상세 리포트의 전체 합계가 비어 보임.
    • 원인: 셸이 리포트 컴포넌트에 그 페이지의 행 슬라이스만 전달 → 컴포넌트가 전체 합계를 알 수 없음.
    • 해결: 데이터 준비 함수(setEstimateList/setEstimateDtl 등)에서 전체 합계를 계산해 MAIN.GT_* 에 실어 보냄.
    • 근거: 각 화면 index.vue 의 set* 함수.

    DevExpress ↔ HTML 뷰어 전환/롤백

    호출부는 MENU_PATH 만 /cms/popup/CmsReportPopup(DevExpress) ↔ /cms/popup/CmsHtmlReportPopup(HTML) 로 바꾼다. DevExpress 호출 코드는 남겨두어 경로 원복만으로 즉시 롤백 가능. 신규 리포트 = reports/ 에 .vue 1개 + 셸 REPORTS 레지스트리 한 줄.

    2. 공통 버튼 (EBtn / EGridBtn)¶

    2.1 아이콘 전용 버튼(+/−, excel 등)의 아이콘이 오른쪽으로 치우침¶

    • 증상: 좁은 정사각형 아이콘 버튼에서 글자/아이콘이 가운데가 아닌 오른쪽으로 쏠림.
    • 원인: EGridBtn 이 항상 <e-btn><slot/></e-btn> 래퍼로 슬롯을 넘겨, 내용이 비어도 EBtn 의 hasSlot 이 true(빈 슬롯도 Fragment vnode로 옴) → 아이콘에 ml-1(좌측 마진)이 붙음.
    • 해결: EGridBtn 이 슬롯 내용이 없으면 u-btn 에 슬롯을 아예 안 넘김(v-if="hasContent") → EBtn 이 아이콘 전용(.icon, 좌우 대칭 패딩·마진0)으로 렌더해 중앙 정렬.
    • 근거: src/components/auto/app/EGridBtn/index.vue(hasContent), EBtn/index.vue(.icon 클래스).

    2.2 그리드 add/delete 버튼 색·너비 통일¶

    • 방식: EGridBtn 에서 button-type 별 기본 색을 분기 — add → normal-line, delete → delete, 그 외 → grid-button. 사용처에서 color 명시 시 그대로 우선.
    • 정사각형: 슬롯이 빈 아이콘 전용 버튼(+/−, excel 등)은 너비 30px + min-width:0 로 통일. 텍스트 버튼(ATFILE 등)은 내용 폭 유지.
    • 근거: EGridBtn/index.vue propParams.

    버튼 색 클래스

    <e-btn color="..."> 는 CSS 클래스로 적용된다(예 normal-line = src/styles/cal-theme.scss, delete = global.scss). 색 목록은 코드 컨벤션 참고.

    3. 팝업 (EDialog)¶

    3.1 팝업 영역 밖(딤 배경) 클릭으로 닫기¶

    • 요구: X 버튼뿐 아니라 팝업 박스 밖을 클릭해도 닫히게.
    • 해결: EDialog 는 커스텀 오버레이(.e-dialog-overlay > .e-dialog) 구조. 오버레이에 @click.self="closeButtonClick" 추가 → 딤 영역 클릭 시 X 버튼과 동일하게 닫힘(reject). .self 라 팝업 내부 클릭·내부 셀렉트(별도 오버레이)는 영향 없음.
    • 근거: src/components/manual/app/EDialog/index.vue.

    9.1 az acr build 가 UnicodeEncodeError: 'cp949' codec 로 실패¶

    • 증상: 프론트 배포의 Build image in ACR 스텝에서 아래로 죽음(백엔드 배포는 통과). 
      UnicodeEncodeError: 'cp949' codec can't encode character '✓' ...
Error: az acr build ...
    • 원인: az acr build 가 스트리밍하는 빌드 로그에 vite 가 찍는 ✓(U+2713) 가 들어있는데, 한국어 Windows 로케일(cp949)이 이 문자를 인코딩 못 해 az 가 크래시. az 는 번들 Python 을 격리 모드(-IBm) 로 실행해 PYTHONIOENCODING/PYTHONUTF8 등 환경변수를 무시하므로 env 로는 못 고친다. 백엔드(gradle)는 해당 문자를 출력하지 않아 영향 없음.
    • 해결: 러너 시스템 로케일을 UTF-8 로 변경 + 재부팅. intl.cpl → 관리자 옵션 → "Beta: 세계 언어 지원을 위해 Unicode UTF-8 사용" 체크(또는 HKLM\SYSTEM\CurrentControlSet\Control\Nls\CodePage 의 ACP/OEMCP/MACCP=65001). 재부팅 후 GetACP=65001 → az 출력이 UTF-8 로 나가 정상.
    • 대안(미사용): 빌드 스텝에서 az 번들 python 을 python -I -X utf8 -m azure.cli acr build ... 로 직접 호출 — 커맨드라인 플래그(-X utf8)는 격리모드에도 적용된다.

    • 해결: 깨진 반응성 다리를 우회하고 위젯 인스턴스 API를 신뢰 원본으로 쓴다.
      • @initialized="fnInitFrt" 로 위젯 인스턴스 확보(this.frtInstance = e.component) — $refs 대신.
      • 조회(fnSearch) 시작부에서 frtInstance.option('value') 를 읽어 search.FRT 에 반영(신뢰 원본).
      • 리셋(fnReset)은 frtInstance.option('value', [전체]) 로 직접 세팅(v-model 이 안 먹으니).
      • 초기 표시는 data() 초기값(born-with-value; 위젯 생성시점 값은 채택됨) + @value-changed e.value 배열가드 + 검증부 !Array.isArray 방어.
      • FRT 단일 필드: 검색 상태를 S_FRT(배열)+FRT(문자열) 2필드에서 FRT(배열) 하나로 통합. 백엔드용 문자열('ALL'/콤마조인)은 fnSearch 전송 시점에만 파생(백엔드 계약 불변).
    • 근거: pages/fds/FdsFeederageMgt/index.vue·FdsInvoice/index.vue 의 fnInitFrt/fnSearch/fnReset/fnSetFRT/검증부. — PR #109.

    13. 무로그인 공개 팝업 (CmsImageCarouselPopup)¶

    수리 이미지 뷰어(CmsImageCarouselPopup)는 포탈/외부에서 로그인 없이 URL(?COMP_CD=&MNGT_NO=)로 여는 공개 팝업이다. window.open 독립 창(App.vue 가 /popup/ 은 셸 없이 풀스크린 렌더 — 레거시 layout:'blank' 동등).

    13.1 팝업을 열면 /login 으로 튕김¶

    • 증상: 무세션(비로그인) 상태로 팝업 URL 진입 시 이미지 대신 로그인 화면으로 리다이렉트. (레거시는 그냥 열렸음.)
    • 원인: 베이스 mixin(src/mixins/page/index.ts)의 beforeMount 가 모든 화면에서 insertVisitLog(MENU_ID)(POST /api/insertVisitLog)를 호출하는데, 이 엔드포인트는 세션 필요(permit-all 아님)라 무세션 팝업에선 401. $http 인터셉터는 401 이면 quiet 여부와 무관하게 authRedirect()(→router.push('/login')) → 튕김. 팝업이 실제로 쓰는 API 2종(/api/crs/repair/disabledFileExtList·/api/file/getBase64ImageList)은 이미 permit-all(200)이라 무관 — 엔드포인트 permit-all 만으로는 부족하고, 베이스 mixin 의 방문로그 텔레메트리가 공개 화면을 깬 것.
    • 해결: 방문로그는 "메뉴 화면 방문" 기록이므로 메뉴 컨텍스트(context.MENU_ID)가 있을 때만 호출. 공개 팝업은 activeTabMap 이 비어 MENU_ID 없음 → 스킵 → 401/리다이렉트 제거(실화면은 menuAuthGuard 가 MENU_ID 세팅 → 기존대로 기록). — PR #124.
    • 근거: src/mixins/page/index.ts beforeMount 가드. 401 인터셉터는 인증/로그인 §401 처리.

    레거시는 왜 안 튕겼나

    백엔드 동작은 레거시=V2 동일하게 무세션 insertVisitLog 에 401 을 낸다(라이브 대조 확인). 차이는 프론트 — 레거시 Nuxt2 컨텍스트 redirect() 는 페이지 로드 후 도착하는 비동기 401 엔 사실상 no-op 이라 401 이 조용히 삼켜져 팝업이 그냥 열렸을 뿐, 진짜 익명-안전했던 게 아니다. V2 는 router.push 라 실제 네비게이트되며 잠복 버그가 표면화됐다(이번 수정으로 레거시보다 오히려 정상).

    13.2 팝업 배경이 흰색 (레거시는 검정)¶

    • 증상: 레거시 이미지 뷰어는 다크(#111) 배경인데 V2 는 흰색.
    • 원인: 마이그레이션 때 ImageCarousel 을 밝은 테마로 재스타일 + 레거시의 페이지 다크 배경(#__nuxt #__layout { background:#111 })을 "v2 미해당"이라 제거. V2 는 /popup/ 을 셸 없이 router-view 로 풀스크린 렌더해 v-app 흰 배경이 비쳤음.

    14. ag-grid 시간(HHMM) 셀 — 재편집 시 입력 막힘¶

    17. 미인증 진입 시 401 3건 — 부트스트랩 병렬 발사 (관측 데이터 해석 주의)¶

    • 증상: 실패 요청 TOP·에러율 지표에 /api/session·/api/menuMap·/api/languageMap 401 이 항상 세 개 세트로 올라온다(운영 실측 최근 7일 각 44~46건).
    • 원인: plugins/bootstrap.ts 가 셋을 Promise.all 로 병렬 발사해, 세션이 없는 진입(딥링크·세션 만료·로그인 페이지에서 뒤로가기)에서 셋 다 401 이 된다. menuMap/languageMap 은 로그인해야 받는 데이터라 미인증 상태에서 보낼 이유가 없었다.
    • 해결: 세션을 먼저 확인하고 실패하면 나머지 둘을 아예 보내지 않는다(기존 catch 가 그대로 받고, http 인터셉터가 /login 으로 보낸다). 진입당 401 이 3건 → 1건. 부팅 지연은 사실상 없다 — 운영 p50 이 $session 18.7ms / languageMap 61.2ms / menuMap 106.7ms 로 세션이 셋 중 가장 싸서 병렬 ~107ms → 직렬 ~126ms(+19ms). — PR #146.
    • 남는 1건은 정상이다 — /api/session 401 은 "로그인돼 있나"를 묻는 프로브 자체다. 서버 세션 유효성은 물어봐야 알 수 있으므로(HttpOnly 쿠키) 원리상 제거 대상이 아니다. 판단 기준은 분당 1건=일상, 2건=드물지만 정상, 10초 내 5건 이상 클러스터=자동화 스캔/리다이렉트 루프 의심.
    • ⚠️ 과거 데이터와 비교할 때: 2026-08-25(PR #146) 이전 구간은 진입 1회당 401 이 3건이라 그만큼 부풀어 있다. 백엔드 CmsAzureLogService 는 401 을 Success == false 로 실패에 포함해 집계하므로(에러율 시계열·요약·실패 요청 TOP 3곳) 배포 전후를 그대로 비교하면 에러율이 개선된 것처럼 보인다. 이 화면은 트래픽 자체가 적어(헬스체크 제외 분당 p50 4건) 에러율(%)이 구조적으로 과장되니, 스파이크는 % 가 아니라 실패 건수/분모로 판단한다(툴팁이 실패 n / 전체 m 을 병기 — PR #147).

    18. e-html-editor — 읽기 전용인데 툴바가 그대로 보임¶

    • 증상: 비관리자가 공지 상세를 열면 편집이 안 되는데도 상단에 서식 툴바(2줄)가 회색으로 깔려 있다. 클릭해도 아무 일이 없는 죽은 UI 인데 본문이 그만큼 아래로 밀린다.
    • 원인: :read-only 는 이미 걸려 있었다. DevExtreme 의 readOnly 는 툴바 버튼을 비활성(회색)만 시킬 뿐 숨기지 않고, dxHtmlEditorToolbar 에는 visible 옵션 자체가 없다(container/items/multiline 뿐). EHtmlEditor 가 <dx-html-editor-toolbar> 를 무조건 선언하고 있었으므로 항상 그려졌다.
    • 해결: toolbar 옵션이 아예 없으면 Quill toolbar 모듈이 붙지 않아 툴바 DOM 이 생성되지 않는다(ui.html_editor.js _getModuleConfigByOption 이 값 미정의면 undefined 반환). EHtmlEditor 에서 <dx-html-editor-toolbar v-if="!readOnly"> 로 렌더 자체를 끊는다. readOnly 는 $attrs 통과 대신 prop 으로 선언 — 호출부가 :read-only 를 쓰느냐 :readOnly 를 쓰느냐에 따라 $attrs 키가 달라져 판정이 불안정하기 때문이고, 값은 propParams 로 다시 실어 보내 편집 잠금 동작은 그대로다. — PR #152.
    • 런타임 토글은 안전하다 — 툴바 유무가 바뀌면 devextreme-vue 가 resetOption('toolbar') → DevExtreme _invalidate() 로 에디터를 통째로 재생성한다. 값(value)은 위젯 옵션이라 보존된다(실측: 토글 전후 본문 862자 동일). 조회 결과에 따라 read-only 가 바뀌는 화면(CsmRequestMgt)이 여기 해당.
    • ⚠️ 다만 첫 렌더에 확정하는 편이 낫다 — 재생성 비용이 있으므로 isAdmin 같은 세션 파생 플래그는 mounted() 가 아니라 created() 에서 잡는다. 늦게 잡으면 화면을 열자마자 툴바가 한 번 깜빡인다.

    19. HTML 리포트 인쇄 — 푸터가 다음 장으로 밀리거나 합계블록과 겹침¶

    화면 뷰어는 멀쩡한데 브라우저 PDF 로 뽑으면 무너지는 증상들. 원인이 서로 달라 하나씩 본다.

    • ① 푸터가 페이지 하단에 안 붙는다 / 다음 물리 페이지 맨 위로 밀려난다
    • 인쇄 CSS 가 .hr-page{height:auto} 로 페이지 박스를 없애고 있었다. 그러면 (a) 남는 공간이 없어 푸터의 margin-top:auto 가 접혀 내용 바로 뒤에 붙고, (b) 내용이 A4 를 1mm 만 넘어도 푸터 블록이 통째로 다음 장으로 넘어간다.
    • 해결: .hr-page{height:297mm; box-sizing:border-box; position:relative} 로 한 장에 고정하고, 푸터(.hr-foot)는 position:absolute; bottom:12mm 로 흐름에서 뺀다. 과거 "한 장 걸러 빈 페이지"는 min-height:297mm 에 padding 24mm 가 더해져 321mm 가 되던 것이 원인이라, border-box 를 명시하면 재발하지 않는다(실측: .hr-page 수 = PDF 물리 페이지 수).
    • ② 마지막 행과 푸터 구분선이 붙어 보인다
    • 푸터가 흐름 밖이라 스스로 간격을 못 만든다. 셸이 예약하는 건 footerPx(푸터 높이)뿐이라 행이 구분선 바로 위까지 찬다.
    • 해결: computePages() 에서 footGapPx = 4mm 를 함께 예약.
    • ③ 마지막 장에서 합계블록(GRAND TOTAL/매트릭스)이 푸터를 덮는다
    • 분할 루프가 usableForRows(합계블록 자리 미반영) 로 담다가 행이 소진되면 그 장이 곧 마지막 장이 되는데, 그 경로엔 grandPx 예약이 없었다.
    • 해결: j === n 이면 usableLast 안에 들어올 때까지 행을 되돌려 넘치는 행을 다음(진짜 마지막) 장으로 보낸다.
    • ④ 페이지당 1행씩만 나온다(짧은 리포트일수록 심함)
    • grandPx 를 푸터 상단 − tbody 바닥 으로 재고 있었다. 푸터는 margin-top:auto 라 측정패스에서 남는 공간만큼 밀려나므로 그 빈 공간이 통째로 합계블록 높이로 잡힌다 → usableLast 가 1px 로 붕괴.

    21. FormData 를 $axios.post 로 보내면 본문이 {} 로 사라진다¶

    • 증상: multipart 엔드포인트 호출이 실패한다. 서버는 MultipartException → InvalidContentTypeException: ... content type header is application/json. 에러로그의 PAYLOAD 는 {"MAIN":{}} 처럼 키만 남고 값이 빈 객체다.
    • 원인: axios 인스턴스에 기본 헤더 Content-Type: application/json 이 박혀 있다(util/http/index.ts). axios 1.x 의 transformRequest 는 Content-Type 에 application/json 이 있으면 FormData 를 그대로 두지 않고 JSON.stringify( formDataToJSON( data ) ) 로 치환한다. Blob/File 파트는 {} 가 되어 본문이 통째로 소실된다. 헤더만 틀린 게 아니라 데이터가 사라지는 것이 핵심이다.
      • 레거시(axios 0.21.4)는 FormData 를 건드리지 않아 같은 코드가 우연히 동작했다. 0.x→1.x 업그레이드로 semantics 가 바뀐 것이라, 레거시에서 멀쩡하던 화면이 V2 에서 조용히 깨진다.
    • 해결: request 인터셉터에서 cfg.data instanceof FormData 면 cfg.headers.setContentType( undefined ). ★인터셉터가 transformRequest 보다 먼저 실행되므로 이 시점에 벗겨야 한다. 그러면 xhr 어댑터(resolveConfig: isFormData → setContentType(undefined))가 다시 지우고 브라우저가 boundary 를 붙인 multipart/form-data 를 만든다.
    • 호출부 규약: multipart 는 $axios.multipart( url, form ) 를 쓴다($axios.post 금지). http.multipart 가 넘기는 Content-Type: multipart/form-data(boundary 없음)는 실제로 전송되지 않는다 — JSON 변환 분기를 회피하는 마커이고 최종 헤더는 브라우저가 만든다.
    • 회귀 테스트: src/util/http/__tests__/http.formdata.spec.ts. 가드가 사라지면 expected '{"MAIN":{}}' to be an instance of FormData 로 실패한다 — 이 문자열이 실제 운영 장애의 와이어 본문이었다.
    • ★진단이 늦어진 이유: 백엔드가 MultipartException 을 전부 "네트워크 문제니 다시 시도"(MSG000429)로 안내해, 재시도해도 100% 실패하는 상황에 재시도를 유도했다(같은 날 40회). 백엔드에서 원인 체인에 InvalidContentTypeException 이 있으면 형식 오류로 갈라 응답하도록 별도 수정했다.

    }

      • 재현 시그니처: 닫기 직후 그 메뉴의 insertVisitLog 가 한 번 더 발화(재마운트 증거).
    • 해결: 활성 탭 닫기(X·Close·복수 닫기 모두)는 이웃/대상 탭으로 await router.push 를 완료한 뒤 스토어에서 제거한다. 닫힐 화면은 평범한 탭 전환으로 비활성화된 뒤 캐시에서 조용히 파기된다. 래퍼/props 정리 워처도 같은 이유로 flush:'post' + 현재 라우트 제외.
    • 같은 계열 함정 — Refresh 재마운트 시 codeMap 유실: 재진입 내비게이션은 codeData 가드(router/guards.ts)가 record.instances 존재를 보고 prefetch 를 생략하므로 그 시점 슬롯 vnode 의 props 엔 codeMap 이 없다. 우클릭 Refresh 가 그 props 로 재마운트하면 화면이 codeMap.XXX 에서 죽는다 → TabWorkspace 가 최초 진입 때 받은 props 를 탭이 열려있는 동안 보존해 재마운트에 재사용한다(레거시 RouterAlive refresh 와 동일 의미). 탭을 닫으면 버려지므로 다음 오픈은 새로 prefetch 된다.

    26. 팝업을 열었을 뿐인데 화면이 통째로 리로드된다 (dev 한정)¶

    • 증상 — 뷰어 버튼 등 팝업을 여는 버튼을 눌렀는데 페이지가 새로고침된 것처럼 초기화된다. 재현이 들쭉날쭉하고, 한 번 겪은 뒤에는 한동안 안 난다.
    • 원인 — router/index.ts 의 stale 청크 자가치유가 발동한 것이다. 배포 후 옛 해시 청크가 404 날 때 화면이 먹통이 되는 걸 막으려고 router.onError / vite:preloadError 에서 window.location.assign() 으로 하드 이동한다. 
      const STALE_CHUNK_RE = /Failed to fetch dynamically imported module|error loading dynamically imported module|.../i
      dev 서버에서 의존성 재최적화가 걸리면 같은 문구의 에러가 난다(504 Outdated Optimize Dep). $dialog 는 팝업 화면을 동적 import 하므로, 그 상태에서 팝업을 여는 순간 이 정규식에 걸려 하드 리로드된다. 리로드되면서 캐시가 새로 잡히니 그 뒤로는 안 난다.
    • 확인 — 리로드를 넘어 살아남는 값이라 사후에도 볼 수 있다. 
      sessionStorage.getItem('vp:chunk-reload')   // 경로가 있으면 자가치유가 돌았다는 뜻
      Network 탭의 504 (Outdated Optimize Dep) 나 /assets/*.js 404 가 같이 보이면 확정.
    • 처방 — dev 는 rm -rf node_modules/.vite → vite 재기동 → 강력 새로고침. 운영에서 같은 증상이면 그건 배포 직후 stale 청크라 의도대로 동작한 것이다.

    27. 첨부 목록에 레거시 문서가 안 보인다 (selectFileList UNION 분기)¶

      if (StringUtils.equals(SEARCH.DOC_TYPE, "RP")) {

    28. 메시지 줄바꿈이 \n 글자 그대로 보인다¶

    • 증상 — $message.warning( $lang('MSGxxxxxx') ) 결과가 ... 입니다. \n\n사용 가능한 ... 처럼 백슬래시-n 이 그대로 출력된다.
    • 원인 — 코드가 아니라 사전 데이터다. EMsgBox 는 이미 white-space: pre-line 이라 실제 개행이면 정상 렌더된다. TB_CMS_DATA_DIC 에 개행을 \n 두 글자로 입력한 항목만 이렇게 보인다(2026-09-03 기준 사전 전체에서 MSG000400 1건, 정상 항목 MSG000428~431 은 실제 개행).
    • 처방 — 코드에서 일괄 치환하지 말 것(정상 항목까지 건드린다). 해당 사전 항목만 실제 줄바꿈으로 수정한다.
    • 확인법 — /api/languageMap 응답을 받아 JSON.stringify(value) 로 보면 \\n(리터럴) 과 \n(실제 개행) 이 구분된다.

    29. 체크박스 컬럼(chk: true)의 체크박스가 왼쪽으로 치우친다¶

    • 증상 — 체크박스 전용 컬럼인데 체크박스가 셀 중앙이 아니라 왼쪽에 붙고, 헤더의 전체선택 체크박스와 행 체크박스가 서로 몇 px 어긋나 보인다.
    • 원인 두 가지
    • 헤더와 셀의 중앙 정렬 방식이 다르다. global.scss 의 .ag-header-checkbox-center 는 justify-content: center, .ag-cell-checkbox-center 는 padding-left: 8px 로 왼쪽 고정이다.
    • balham 이 체크박스에 margin-right: 12px(--ag-cell-widget-spacing)를 준다. 셀 텍스트와 띄우려는 값인데 체크박스만 있는 컬럼에는 띄울 텍스트가 없다. flex 가 체크박스 16px + 여백 12px = 28px 를 40px 안에서 중앙에 놓으므로 체크박스가 6px 왼쪽으로 밀린다. 
      셀:   [ 311 ─────────── 351 ]  중심 331
내용: [ 317 ☑16 ][ 여백 12 ]   → 체크박스 중심 325
    • 처방 — 두 클래스를 같은 방식(중앙)으로 맞추고 margin-right 를 없앤다. 
      .ag-header-checkbox-center,
.ag-cell-checkbox-center {
    display: flex !important;
    align-items: center;
    justify-content: center;
    padding-left: 0 !important;
    padding-right: 0 !important;
}
.ag-header-checkbox-center .ag-header-select-all,
.ag-cell-checkbox-center .ag-selection-checkbox {
    margin-right: 0 !important;
}
    • ⚠️ 전역 규칙을 고치면 chk: true 를 쓰는 다른 화면(EirExportIssue, CmsMultiCustomerPopup 등)도 같이 움직인다. EAttachFileGrid 는 자기 그리드(.attach-file-ag)로 스코프를 걸어 적용했다. 원인이 전역 CSS 라 다른 화면도 같은 증상일 가능성이 높지만, 범위를 넓히는 건 별건으로 둔다.
    • 진단 팁 — 눈으로 재지 말고 getBoundingClientRect() 로 셀 중심과 체크박스 중심을 찍어 비교하면 원인(정렬 vs 마진)이 바로 갈린다.
