    HTTP / API 연동¶

    HTTP 는 src/util/http 의 axios 인스턴스로 통합되어 있고, 전역 프로퍼티 this.$http(= this.$axios)로 모든 화면에서 사용합니다.

    // src/main.ts
app.config.globalProperties.$http  = http
app.config.globalProperties.$axios = http

    호출 종류¶

    메서드 설명
    http.$post(url, params, cfg?) 표준 POST. 사용자 컨텍스트 헤더 자동 주입(USER_ID/CORP_CD/COMP_CD/CUST_CD)
    http.post(url, params, cfg?) 원시 POST(컨텍스트 주입 없음)
    http.$session() GET /api/session (부트스트랩)
    http.$menu() POST /api/menuMap (부트스트랩)
    http.$lang({ LANG_CD }) POST /api/languageMap (부트스트랩)
    http.login(USER_ID, USER_PWD, LANG, CORP_CD) POST /api/login
    http.fileDown({ FILE_SN }) /api/file/downloadFileNas

    $post 는 auth/ui 스토어에서 사용자/회사/고객 컨텍스트를 읽어 헤더로 넣어줍니다. 일반 조회/저장은 대부분 $post 를 씁니다.

    응답 처리 (인터셉터)¶

    src/util/http 의 응답 인터셉터가 공통 처리를 합니다.

    • 200 → response.data 자동 언랩(화면은 result.data... 형태로 사용).
    • 401 → authRedirect() 호출 → /login 으로 이동(main.ts 에서 setAuthRedirect(() => router.push('/login')) 등록).
    • 에러 → data 로 reject + 사용자 알림(notification).
    • 로딩바 → 요청 시작/종료에 맞춰 loading 스토어 갱신. config.quiet === true 면 오버레이 억제.

    화면에서의 전형적 호출¶

    // 1) 공통 프로시저 실행 (dataset 기반) — 조회/저장 통합 엔드포인트
this.$axios.$post(
  `${vendorCommonUrlPrefix}/executeVendorCommonProcedure`,
  { DATASET: dataset.SEARCH_NEW }
).then( ( result ) => {
  const rows = result.data[ procedureName ].P_RS || []
} )

// 2) 전용 엔드포인트 직접 호출
this.$axios.$post( '/api/eir/issueEirNew', payload )

    조회/저장 통합 엔드포인트

    공통 프로시저 호출은 조회·저장 구분 없이 executeVendorCommonProcedure 하나로 보낸다(PR #110 으로 EIR 2화면까지 전 모듈 전환 완료). 기존 select/saveVendorCommonProcedure 는 하위호환으로 남아 있으나 실사용처 0 이다(주석 잔재 2건뿐). 백엔드 배경은 ADR-0004.

    post vs $post — 선사 스키마 오검증 함정

    원시 post/$axios.post 는 사용자 컨텍스트(COMP_CD 등)를 싣지 않는다. COMP_CD 가 빠지면 백엔드의 선사 스키마 switch 가 default(LINER=SNKO) 로 떨어져, HALK/HSLI 상태에서도 SNKO 기준으로 동작하는 조용한 오류가 난다(실사례: TES 엑셀 업로드 검증이 항상 SNKO 마스터로 대조되던 것 — PR #113 에서 $post 전환으로 수정). 일반 조회/저장은 $post 를 쓴다.

    /api 프록시 (개발 서버)¶

    개발 시 /api 요청은 vite.config.ts 의 프록시가 백엔드로 전달합니다.

    server.proxy['/api'] = {
  target: API_URL,        // .env 의 API_URL (예: http://localhost:9041)
  changeOrigin: true,
  rewrite: (p) => p.replace(/^.../,'')   // NUXT_PROXY_URL 접두 제거
}
    • 프록시 타깃은 .env 의 API_URL 만 읽습니다(로컬 단일 소스). .env.development/.env.production 의 API_URL(예: http://pilos2-backend:8080)은 dev 프록시에 쓰이지 않습니다 — 자세한 이유는 vite.config.ts 주석과 빌드/배포/환경 참고.
    • 그 외 프록시: /WebDocumentViewer(DevExpress 문서 뷰어), /sendSIPG(SIPG EIR 취소 ESB).
    • 배포 환경에서는 동일 출처로 백엔드에 붙으므로 프록시가 필요 없습니다.
