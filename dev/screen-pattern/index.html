    화면 작성 패턴¶

    화면 하나는 src/pages/<module>/<Screen>/ 폴더에 두며, 보통 두 파일로 구성됩니다.

    src/pages/eir/EirExportIssue/
├─ index.vue      ← 템플릿 + 로직 (UI, 그리드 정의, 메서드)
└─ dataset.js     ← 저장프로시저 메타데이터 (PACKAGE/PROCEDURE/PARAM/CURSOR)

    화면은 Composition API 가 아니라 Options API + pageMixin 패턴을 따릅니다.

    index.vue 골격¶

    <template>
  <e-content-layout @btn-reset="fnReset" @btn-search="fnSearch" @btn-send="fnSend">
    <e-card-grid :title="'Search'">
      <ag-grid-vue :grid-options="searchGridOptions" />
    </e-card-grid>
    <!-- 추가 그리드/폼 ... -->
  </e-content-layout>
</template>

<script>
import pageMixin from '~/mixins/page'
import { AgGridAdapter } from '~/util'
import dataset from './dataset'

export default {
  mixins: [ pageMixin ],     // codeMap prop, 방문로그(visitLog), args 처리 제공

  codeData () {              // 정적: 가드(codeDataGuard)가 호출해 공통코드 프리페치
    return {}                // 예) { CMM: 'SP_GET_COMMON_CODE', ... }
  },

  data () {
    return {
      search: {},            // 검색 폼 상태
      searchGridOptions: null,
      searchGridAdapter: null
    }
  },

  beforeMount () {
    this.searchGridOptions = this.fnGetSearchGridOptions()  // 컬럼 정의(인라인)
  },

  mounted () {
    this.searchGridAdapter = AgGridAdapter.of( this.searchGridOptions )
    this.fnReset()
  },

  methods: {
    fnGetSearchGridOptions () { return { columnDefs: [ /* ... */ ] } },

    fnSearch () {
      // dataset 의 PARAM/CURSOR 를 런타임 값으로 채운 뒤 공통 프로시저 호출
      dataset.SEARCH_NEW[0].PARAM = { ...this.search }
      this.$axios.$post(
        `${vendorCommonUrlPrefix}/executeVendorCommonProcedure`,
        { DATASET: dataset.SEARCH_NEW }
      ).then( ( result ) => {
        const rows = result.data[ procedureName ].P_RS || []
        // 그리드 반영 ...
      } )
    },

    fnSend () {
      this.$axios.$post( '/api/eir/issueEirNew', { /* ... */ } )  // 전용 엔드포인트 직접 호출
    }
  }
}
</script>

    dataset.js 골격¶

    dataset.js 는 DB 저장프로시저 호출 메타데이터를 담습니다. 화면 로직(fnSearch 등)에서 PARAM/CURSOR 를 채운 뒤 공통 프로시저 실행 엔드포인트로 보냅니다.

    export default {
  SEARCH_NEW: [
    {
      PACKAGE: 'PKG_EEIR',
      PROCEDURE: 'SP_GET_BKNOLIST4EXPORT',
      PARAM: {},          // fnSearch 에서 채움
      CURSOR: { P_RS: [] } // 출력 커서 → 결과 행
    }
  ],
  SET_LOG: [ /* 로그 적재 프로시저 */ ],
  DEL_LOG: [ /* ... */ ]
}

    역할 분리 요약¶

    위치 담는 것
    index.vue 템플릿 e-* 레이아웃 + ag-grid/DevExtreme 배치
    index.vue 스크립트 생명주기, 그리드 컬럼 정의(fnGetXxxGridOptions), 검색/저장/전송 메서드
    dataset.js 저장프로시저 메타(PACKAGE/PROCEDURE/PARAM/CURSOR)
    codeData() 가드가 프리페치할 공통코드 선언 → codeMap prop 으로 주입

    두 가지 호출 방식¶

    1. 공통 프로시저 실행 — executeVendorCommonProcedure 에 dataset 을 보내 DB 프로시저를 직접 구동(목록 조회/CRUD 의 다수). 조회·저장 통합 엔드포인트다(구 select/saveVendorCommonProcedure 는 2026-08 EIR 까지 전환 완료 — 더 이상 사용하지 않는다).
    2. 전용 엔드포인트 — this.$axios.$post('/api/eir/issueEirNew', ...) 처럼 백엔드 컨트롤러를 직접 호출(발행/연동 등 도메인 로직).

    자세한 호출 규약·헤더 주입은 HTTP / API 참고.

    조회 결과 처리 (0건 규약)¶

    조회 응답을 그리드에 넣을 때 0건도 하나의 결과로 취급합니다. 두 가지를 지킵니다.

    .then( ( result ) => {
  const rows = result.data[ procedureName ].P_RS || []

  this.mainGridAdapter.setItems( rows )          // ① 조건 밖에서 항상 호출

  if ( rows.length > 0 ) {
    this.$notify( this.$lang( 'MSG000004' ) )     // 조회가 되었습니다.
  } else {
    this.$notify.warn( this.$lang( 'MSG000016' ) ) // ② 조회된 데이터가 없습니다.
  }
} )

    ① setItems 는 if 밖에서 — if ( rows.length > 0 ) 안에 두면 0건 응답에서 호출 자체가 안 돼 직전 조회 결과가 화면에 그대로 남습니다. "데이터가 없습니다" 알림은 떴는데 이전 행이 보이는 상태가 됩니다. 앞에서 clear() 를 부르는 형태도 동일하게 유효합니다. 상세 그리드(마스터 행 클릭 → 상세 조회)에서 특히 잘 드러납니다 — 다른 행을 눌렀는데 이전 행의 상세가 남습니다.

    ② 0건 알림은 $notify.warn — 성공($notify, 초록)과 같은 모양이면 사용자가 성공/빈결과를 구분하지 못합니다. 모달($message)은 확인 클릭을 강요하므로 조회 0건에는 쓰지 않습니다. 모달은 "선택된 행이 없습니다"(MSG000009)처럼 사용자 조작을 되돌려야 하는 경우에만 씁니다.

    메시지 코드는 조회 성공 MSG000004, 조회 0건 MSG000016(화면에 따라 MSG000390/MSG000393), 선택 행 없음 MSG000009. — PR #143, #148.

    새 화면 추가 체크리스트¶

    1. src/pages/<module>/<Screen>/index.vue 생성(+ 필요 시 dataset.js).
    2. mixins: [ pageMixin ] 적용, 필요한 공통코드는 codeData() 에 선언.
    3. 그리드는 fnGetXxxGridOptions() 로 컬럼 정의 후 AgGridAdapter.of(...). 조회 결과 반영은 위 조회 결과 처리(0건 규약) 절을 따릅니다(setItems 는 조건 밖, 0건은 $notify.warn).
    4. 메뉴 노출은 백엔드 menuMap(MENU_PATH=/module/Screen, MENU_NM) 등록 필요 — 프론트만 추가하면 메뉴/제목이 안 잡힙니다.
    5. push → 배포 시 화면 인벤토리에 자동 반영.
