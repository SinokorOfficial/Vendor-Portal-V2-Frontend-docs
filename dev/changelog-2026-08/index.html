    2026-08 변경 이력¶

    날짜 자릿수 미달로 인한 공통 프로시저 500 차단 (PR #158)¶

    • 증상 — 날짜 칸이 비어 보이는데 조회/저장 시 500(StringIndexOutOfBoundsException). 운영 에러로그 실측 18건(2025-07-16~2026-01-21, 유저 8명), 잘린 길이 1/2/4/6/7자로 8자가 나온 적은 없다. V2 에서도 동일 재현(EirResponseLog → FM_DT="2026" → HTTP 500).
    • 원인은 화면이 아니라 EDateBox — 타이핑 중 매 입력마다 update:modelValue 를 emit 하는데 그 값은 숫자만 남길 뿐 길이검사가 없고, onInputFocusOut 은 자릿수 미달이면 표시만 지우고 emit 하지 않았다. 화면은 빈칸인데 모델엔 "2026" 이 남아 그대로 전송됐다. AgEDateBoxEditor 가 이를 v-model 로 감싸 그리드 커서 컬럼도 같은 경로.
    • 백엔드 규칙(무수정) — 인자·커서컬럼이 _DT(8)/_DI(12)/_DY(4)/_DM(6) 로 끝나면 substring(0,N) 을 길이검사 없이 수행. VSL_DT 만 예외. DB 실측 노출면은 FM_DT/TO_DT(조회기간 14화면)·GRP_INV_DT·JOB_DT·INV_DT·APP_DT·TRAN_DT·OEV/IFE/OFD/IED_DT·INP_DT·INST_DI/UPST_DI 로 약 40화면.
    • 수정은 화면별이 아니라 중앙 4곳 — ① ValidateUtil.sanitizeVmsDatasetDates(백엔드 규칙의 거울, 단위테스트 9건) ② util/http/index.ts axios request 인터셉터가 관문 — 자릿수 미달이면 MSG000409 와 함께 요청 자체를 보내지 않는다 ③ EDateBox.onInputFocusOut 이 부분값 표시를 지우지 않아 화면=모델 ④ AgEDateBoxEditor.isCancelAfterEnd 로 미달 셀 커밋 취소. 화면 183 호출부·<e-date-box> 143태그·그리드 컬럼 117개는 무수정.
    • ★관문을 http.$post 가 아니라 인터셉터에 둔 이유 — CmsEmailPopup 이 $axios.post 로 $post 를 우회한다(3곳). $post 에 두면 그 경로가 샌다.
    • 틀리기 쉬운 3가지(전부 실측 확인) — 빈값·null 은 통과시켜야 기간 비운 전기간 조회 5화면이 산다 / 짧은 값 자동 보정 금지(조용한 오저장) / VSL_DT 는 정확 일치로 제외(TES 4화면이 yyyyMMddHHmm 12자를 의도적으로 보내 8자 규칙을 걸면 500 없이 시각이 사라진다). 덤으로 2026/08/31 처럼 백엔드가 2026/08/ 로 썩히던 구분자는 정규화해 보낸다.
    • 상세·재현절차는 트러블슈팅 §20. 잔여: 프론트 경유만 막으므로 다른 클라이언트는 여전히 500 — 배포 후 TB_CMS_ERROR_LOG 의 setDateColumn 건수 추이로 확인한다.

    UserDashBoard 달력 개인 메모 활성화 (PR #157, 백엔드 #111)¶

    • 한 번도 동작한 적 없던 기능 — 프론트에 fnSelectMemo/fnSaveMemo 와 EScheduler 의 add·update·delete 배선이 전부 있었는데 mounted() 의 호출만 주석 처리돼 있었고, 그것들이 부르는 /api/dsh/Home/* 는 V2 에도 레거시에도 없었다(레거시 프론트도 같은 줄이 주석). 테이블(TB_CMS_USER_MEMO)만 남아 있었다 — 운영 데이터 0건, 컬럼이 프론트 기대와 일치해 DDL 없이 붙었다.
    • 백엔드 신설(#111) — dsh 모듈(HomeController/HomeService/HomeDao + 매퍼) 4파일 전부 신규, 기존 파일 수정 0. 경로는 프론트를 고치지 않으려고 프론트가 이미 호출하던 값에 맞췄다(selectUserMemo/saveMemo). 프론트와 동시 배포 필요(백엔드가 늦으면 404 지만 quiet:true+.catch 라 달력만 빈 채로 뜬다).
    • ★잠재 데이터 손상 제거 — getResponseDate 가 new Date(data.startDate + 9*60*60*1000) 였는데 data.startDate 가 Date 객체라 + 가 문자열 연결이 된다("...GMT+0900 (…)32400000"). V8 이 꼬리를 무시해 우연히 맞게 동작했을 뿐 +9h 는 아무 일도 안 하는 연산이었고, 파싱 관용성이 다른 엔진에서 Invalid Date 가 되면 START_DT 가 'NaNNaNNaN' 으로 저장된다. 이 PR 이 바로 그 경로를 켜므로 함께 정정했다.
    • 팝업 바깥 클릭으로 닫기 — DX 22.1 hideOnOutsideClick 을 그냥 true 로 켜면 회귀가 난다(대조 실험): 팝업이 여는 더블클릭의 첫 클릭 직후 열려 전체화면 wrapper 가 이미 떠 있고, 두 번째 클릭의 pointerdown 이 wrapper 로 들어와(+41ms) DX 가 바깥 클릭으로 판정해 자가폐쇄한다(같은 셀 재열기 불가). 함수형 hideOnOutsideClick 으로 열린 뒤 500ms 동안만 바깥 클릭을 무시하도록 해결.
    • fnSelectDash(D-Day 차트)는 백엔드 selectUserDash 가 없어 주석 유지하고 사유를 남겼다. 사용법은 사용자 가이드 getting-started.md 의 「홈 달력 메모」 절 참고.

    CrsInvoice 상세 조회 0건 판정 오류 (PR #154)¶

    • 인보이스 상세가 정상 조회됐는데도 "조회 된 데이터가 없습니다" 경고가 뜨던 결함. fnSearchDetail 의 data 는 세 커서 결과를 전개해 만든 객체인데 data.length > 0 으로 검사해 undefined > 0 = 항상 false → 조회 성공 여부와 무관하게 늘 0건 분기로 빠졌다. 초기 커밋부터 있던 결함이 PR #143(0건 알림 $notify.warn 전환)으로 초록→주황 경고가 되며 드러난 것.
    • truthy 검사로는 반대로 틀린다 — 프로시저가 빈 결과를 줘도 {...undefined} 는 {} 를 만들어 data 는 어떤 경우에도 객체이므로, if (data) 면 0건에도 성공 알림이 뜬다. Object.keys(data).length > 0 로 판정(되돌리기 방지 주석 포함). 같은 패턴(전개 객체를 .length 로 검사) 전수 스캔 결과 다른 화면엔 0건 — 이 자리만의 문제.

    HTML 리포트 — 리포트 레이아웃을 업무 모듈로 이동 + 인쇄 페이지/푸터/자동분할 결함 5건 (PR #153)¶

    • 리포트 레이아웃 파일을 각 업무 모듈 아래로 이동 — cms/popup/CmsHtmlReportPopup/reports/ 에 몰려 있던 5종을 src/pages/crs/reports/(CRS 4종)·src/pages/fds/reports/(SurrenderNotice)로 옮겼다. 셸(CmsHtmlReportPopup)만 cms/popup 에 남고, import 는 상대경로 대신 ~/pages/<모듈>/reports/.... 라우트 경로가 /crs/reports/*·/fds/reports/* 로 바뀌지만 여는 코드가 없다(셸이 import 로만 쓴다).
    • 푸터를 페이지 맨 아래로 — es-foot·el-foot 만 margin-top:6mm(예전에 "짧은 리포트 여백" 때문에 auto 를 뺐던 자리)이라 나머지 3종과 달랐다. 5종 전부 margin-top:auto 로 통일. 마진이 auto 라 셸의 분할 측정(footerPx = 마진 제외 높이)과도 어긋나지 않는다.
    • 인쇄 페이지 박스 고정(핵심) — 인쇄 CSS 가 .hr-page{height:auto} 라 종이에선 ① 짧은 장의 푸터가 위로 붙고 ② 내용이 A4 를 조금만 넘어도 푸터가 다음 물리 페이지로 밀렸다(운영 신고). height:297mm + box-sizing:border-box + 푸터 position:absolute; bottom:12mm 로 해결. 과거 "한 장 걸러 빈 페이지"는 border-box 미지정이 원인이라 재발하지 않는다 — 실측 .hr-page 수 = PDF 물리 페이지 수(1:1).
