    변경 이력¶

    프론트엔드의 주요 변경을 기록한다. 상세 커밋은 git 로그를, 문제 해결 맥락은 트러블슈팅을 참고. 새 항목은 최신이 위로 오도록 해당 월 섹션에 추가한다.

    2026-08¶

    HTML 리포트 — 리포트 레이아웃을 업무 모듈로 이동 + 인쇄 페이지/푸터/자동분할 결함 5건 (PR #153)¶

    • 리포트 레이아웃 파일을 각 업무 모듈 아래로 이동 — cms/popup/CmsHtmlReportPopup/reports/ 에 몰려 있던 5종을 src/pages/crs/reports/(CRS 4종)·src/pages/fds/reports/(SurrenderNotice)로 옮겼다. 셸(CmsHtmlReportPopup)만 cms/popup 에 남고, import 는 상대경로 대신 ~/pages/<모듈>/reports/.... 라우트 경로가 /crs/reports/*·/fds/reports/* 로 바뀌지만 여는 코드가 없다(셸이 import 로만 쓴다).
    • 푸터를 페이지 맨 아래로 — es-foot·el-foot 만 margin-top:6mm(예전에 "짧은 리포트 여백" 때문에 auto 를 뺐던 자리)이라 나머지 3종과 달랐다. 5종 전부 margin-top:auto 로 통일. 마진이 auto 라 셸의 분할 측정(footerPx = 마진 제외 높이)과도 어긋나지 않는다.
    • 인쇄 페이지 박스 고정(핵심) — 인쇄 CSS 가 .hr-page{height:auto} 라 종이에선 ① 짧은 장의 푸터가 위로 붙고 ② 내용이 A4 를 조금만 넘어도 푸터가 다음 물리 페이지로 밀렸다(운영 신고). height:297mm + box-sizing:border-box + 푸터 position:absolute; bottom:12mm 로 해결. 과거 "한 장 걸러 빈 페이지"는 border-box 미지정이 원인이라 재발하지 않는다 — 실측 .hr-page 수 = PDF 물리 페이지 수(1:1).
    • 분할 결함 3건(전부 실측으로 발견) — ⓐ 마지막 행이 푸터 구분선과 붙어 보임 → footGapPx = 4mm 예약. ⓑ 마지막 장에서 합계블록이 푸터를 덮음 — 분할 루프가 행 소진 경로(j === n)에서 grandPx 를 예약하지 않았다 → usableLast 까지 행을 되돌린다. ⓒ grandPx 과대측정 — 푸터 상단 − tbody 바닥 으로 재는데 푸터가 margin-top:auto 라 측정패스의 빈 공간이 통째로 합계블록 높이로 잡혀 usableLast 가 1px 로 붕괴, 페이지당 1행이 됐다 → 본문 마지막 요소의 바닥 기준으로 변경.
    • ★자동 페이지 분할이 2개 리포트에서 아예 안 돌고 있었다 — 셸이 querySelector('tbody') 로 첫 tbody 를 집는데 InvoiceDetail·Estimate 는 데이터 표 위에 메타박스 <table> 이 있어 메타박스 tbody 를 집었다 → n !== list.length → 항상 고정 rowsPerPage 폴백. 2026-06-29 의 실측 분할이 사실상 EstimateList 전용이었던 셈. 데이터 tbody 에 hr-rows 를 붙여 해결하고, Estimate(아이템당 <tr> 2개)를 위해 아이템당 tr 수로 묶어 높이를 재도록 일반화. 결과로 페이지 밀도가 올랐다 — Estimate 100행 9장→7장(12→16행/장), InvoiceDetail 150행 6장→5장(28→31행/장).
    • 검증 — 5종 × 행수 25가지를 A4 뷰포트 + print 미디어에서 실측: 장 높이 297.01mm, 푸터 하단 12mm, 세로·가로 초과 0, 본문 바닥 < 푸터 상단, .hr-page 수 = PDF 물리 페이지 수, 분할 합 = 원본 행수 — 전 케이스 통과. 재현 절차는 트러블슈팅 §19.

    공지사항 화면 <table> 전환 + 읽기 전용 에디터 툴바 숨김 · AdminDashBoard LOG 탭 제거 (PR #152)¶

    • MdmNotice 를 ag-grid → <table> 로 전환 — 공지 목록은 정렬·필터·범위선택·컬럼 리사이즈가 전혀 필요 없는 읽기 전용 게시판인데 ag-grid 를 얹고 있어 헤더 UI 만 무거웠다. 순수 <table> 로 바꾸고 검색 인풋 + 목록을 화면 가운데(폭 70%, 최대 1100px)에 배치, 상단 40px 여백. 12건/페이지 는 실측 기준 — 행 41px, 가용 높이 ≈ 뷰포트 − 284px 이라 12건이면 900px 화면에서도 스크롤이 안 생긴다(15건은 950px, 18건은 1080px 필요). 페이저는 1페이지뿐이어도 항상 그려 목록 높이가 흔들리지 않게 했다(PAGE_LENGTH || 1).
    • 구분(MODULE_DIV) 이 모든 사용자에게 보이던 결함 — 관리자 전용 컬럼인데 조건이 반대로 걸려 있었고(hide 의 의미가 뒤집힘), 더해서 isAdmin 을 mounted() 에서 넣는 바람에 컬럼 정의를 만드는 beforeMount() 시점엔 항상 false 였다. 두 결함이 겹쳐 결과적으로 누구에게나 노출됐다. <table> 전환과 함께 v-if="isAdmin" 으로 정리하고, isAdmin 판정을 created() 로 올려 첫 렌더에 확정한다(세션 스토어만 읽으므로 안전).
    • 읽기 전용 에디터의 죽은 툴바 제거(EHtmlEditor 전역) — 비관리자가 공지 상세를 열면 :read-only 가 걸려 있는데도 서식 툴바 2줄이 회색으로 깔려 있었다. DevExtreme 의 readOnly 는 비활성만 시킬 뿐 숨기지 않기 때문. 툴바 렌더 자체를 끊는 방식으로 바꿨다 → 트러블슈팅 §18. 같이 바뀌는 화면: CmsEmailLog(메일 본문 뷰어, 상시 read-only)·CsmRequestMgt(처리 상태가 N 이 아니면 read-only). CmsEmailPopup·dev/template/control 은 read-only 가 아니라 무변경. 검증은 실제 로그인으로 — admin(ADMIN) 툴바 1 / FVC-TEST(FDS01) 툴바 0, 런타임 토글 0→1 시 본문 862자 보존.
