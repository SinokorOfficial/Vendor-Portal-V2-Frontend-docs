    빌드 / 배포 / 환경변수¶

    명령어 (Node 20 필요)¶

    # Vite5/Vuetify3 는 Node 20 필요
export PATH="/c/Users/USER/AppData/Roaming/nvm/v20.12.2:$PATH"

npm install      # 최초 1회(이관 시 node_modules 제외됨)
npm run dev      # 개발 서버 0.0.0.0:4040
npm run build    # vue-tsc --noEmit && vite build  → dist/
npm run preview  # 빌드 산출물 미리보기 :4040
npm run typecheck# vue-tsc --noEmit
npm run test     # vitest

    Windows 빌드 팁

    포그라운드 bash 에서 crypto.getRandomValues 에러가 나면 백그라운드로 실행하세요. npm run dev 스크립트는 nvm v20 PATH 를 자체 주입합니다.

    환경변수¶

    .env / .env.development / .env.production 세 파일을 사용하며 모두 gitignore 됩니다(실값은 로컬에만). 템플릿은 .env.example.

    변수 용도 노출
    API_URL dev 프록시 타깃(백엔드) 비노출(프록시 전용)
    NUXT_APP_SITE 사이트 식별자(favicon 등) 브라우저 노출
    NUXT_PROFILE_ACTIVE 환경 태그(LOCAL 등) 브라우저 노출
    NUXT_PROXY_URL 프록시 경로 접두(보통 비움) 비노출
    • 브라우저(import.meta.env) 노출은 VITE_* / NUXT_* 접두만(envPrefix).
    • 로딩: npm run dev → .env + .env.development, npm run build → .env + .env.production.
    • 단, dev 프록시 타깃(API_URL)은 vite.config.ts 가 .env 만 읽습니다(로컬 백엔드 고정). 이는 .env.development 의 API_URL=http://pilos2-backend:8080 이 로컬에서 해석 불가해 /api 가 전부 실패하던 문제를 막기 위한 것입니다(레거시 Nuxt 동작 복원).

    보안

    백엔드 비밀값을 .env 에 넣지 마세요 — 빌드 번들에 박혀 노출됩니다.

    CI 품질게이트 (PR 체크)¶

    dev/main 대상 PR 에서 .github/workflows/ci.yml(build-scan 잡)이 실행된다. 리포트 전용·비차단으로 시작하며, 안정화 후 브랜치 보호로 빌드 통과를 필수 체크로 승격할 수 있다. 앱 배포 deploy.yml·문서 배포 docs-deploy.yml 과는 별개다.

    • ① 빌드 게이트 — npm ci → npm run build(vue-tsc 타입체크 + vite build). 타입/구문/import 오류가 머지되는 것을 막는다.
    • ② Trivy 취약점 스캔(리포트) — package-lock.json 의존성의 CRITICAL/HIGH CVE. 결과는 Actions 실행 로그에 테이블로 출력한다(exit-code: 0 비차단).
    • ③ SBOM — CycloneDX(sbom-frontend.cdx.json)를 아티팩트로 업로드.

    Security 탭 대신 Actions 로그

    레포가 private + GitHub Advanced Security 미사용이라 SARIF 를 Security 탭(코드 스캐닝)에 올리면 Resource not accessible by integration 으로 실패한다. 그래서 Trivy 결과는 Actions 로그(format: table)로 남긴다. Security 탭 대시보드가 필요하면 GHAS(유료) 활성화가 전제다.

    액션 태그 함정

    aquasecurity/trivy-action 태그는 v 접두가 필수(@v0.36.0; @0.36.0 은 resolve 실패).

    문서 자동 배포(이 문서 사이트)¶

    문서 소스는 이 레포 안(docs/=매뉴얼, docs-dev/=개발자)에 두고, main push 시 빌드해 별도 레포 Vendor-Portal-V2-Frontend-docs 의 gh-pages 로 발행합니다(백엔드와 동일 패턴).

    프론트 레포 main push (docs/** · docs-dev/** · mkdocs*.yml · requirements.txt · docs-tools/**) 또는 수동 실행(workflow_dispatch)
  └─ .github/workflows/docs-deploy.yml
       npm ci → npx vite build (components.d.ts/typed-router.d.ts 생성)
       node docs-tools/generate-docs.mjs --out docs-dev/reference
       mkdocs build --strict (user→site, dev→site/dev)
       → peaceiris/actions-gh-pages → Vendor-Portal-V2-Frontend-docs:gh-pages
    • 자동 추출 레퍼런스(docs-dev/reference/ — 화면/라우트/컴포넌트/스토어 목록)는 배포 실행 시 현재 src 에서 재생성됩니다. 단 src 변경만으로는 배포가 트리거되지 않으므로(2026-07 src/** 트리거 제거 — 코드 머지마다 Pages 일시 오류에 노출되던 것 방지) 코드가 크게 바뀌어 reference 갱신이 필요하면 workflow_dispatch 로 수동 실행합니다.
    • 빌드는 --strict — 깨진 링크는 경고가 아니라 배포 실패입니다. 특히 개발자 문서(docs-dev/)에서 사용자 매뉴얼(docs/)로 넘어가는 상대링크는 사이트 경계(site vs site/dev)를 넘어 strict 실패하므로 쓰지 말 것 — 발행된 절대 URL 을 씁니다(PR #159 배경).
    • 서술형 문서(이 페이지 등)와 사용자 매뉴얼은 이 레포에서 직접 편집.
    • 모듈 한글명은 docs-tools/module-names.json 에서 관리.

    설정 단계와 인증(GitHub App 시크릿 DOCS_APP_ID/DOCS_APP_PRIVATE_KEY — 2026-08 PAT 에서 전환)은 레포 루트 DOCS-DEPLOY.md 를 참고하세요.
