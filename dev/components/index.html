    공통 컴포넌트¶

    자동 등록 (unplugin-vue-components)¶

    import 없이 템플릿에서 바로 쓰는 컴포넌트는 unplugin-vue-components 가 자동 등록합니다 (vite.config.ts).

    Components({
  dirs: [ 'src/components/auto/app', 'src/components/manual' ],
  extensions: [ 'vue' ],
  dts: 'src/components.d.ts',     // 등록명 타입 자동 생성(권위 있는 목록)
  directoryAsNamespace: true,     // 하위 폴더명을 컴포넌트명 접두로
  collapseSamePrefixes: true      // ECard + Grid → ECardGrid (중복 접두 제거)
})
    • src/components/auto/app/ECard/Grid/index.vue → 등록명 ECardGrid → 태그 <e-card-grid>
    • src/components/auto/app/EBtn/index.vue → EBtn → <e-btn>
    • src/components/manual/app/EHeader/index.vue → EHeader → <e-header>

    전체 목록은 자동 생성

    등록된 모든 컴포넌트와 정확한 태그명은 자동 추출 레퍼런스 › 공통 컴포넌트에 있습니다(빌드 시 src/components.d.ts 기준으로 갱신).

    두 디렉터리¶

    디렉터리 성격 예
    src/components/auto/app 화면에서 조립하는 공통 e-* UI EContentLayout, ECardGrid, EDateBox, ECodeBox, EBtn, EFileUploader
    src/components/manual 앱 셸·그리드 렌더러·도메인 컴포넌트 AppEHeader, AppESideMenu, AgGridVue* 렌더러/에디터, DashboardKbel*, Login

    자주 쓰는 공통 컴포넌트¶

    컴포넌트 용도
    <e-content-layout> 화면 기본 래퍼. btn-search/btn-reset/btn-send 등 액션 이벤트 노출
    <e-card-grid> / <e-card-form> / <e-card-tab> 카드형 그리드 / 폼 / 탭 컨테이너
    <e-code-box> 공통코드 드롭다운(=codeMap 연계)
    <e-date-box> 날짜 선택
    <e-attach-file-grid> 첨부 표준 컴포넌트. 그리드 자체가 드래그&드롭 존이고 조회·업로드·삭제·다운로드·뷰어를 캡슐화. 아래 참고
    <e-btn> 표준 버튼(색상군은 코드 컨벤션 참고)
    <e-grid-btn> / <e-list-btn> 그리드/목록 액션 버튼군

    <e-attach-file-grid> — 첨부 표준¶

    첨부 UI 는 이 컴포넌트로 일원화한다. 변형은 전부 props/이벤트로 처리하고, 화면에서 그리드를 다시 짜지 않는다.

    props 뜻
    mngt-no 파일 그룹 키. 값이 바뀌면 자동 조회하고, 비면 서버 호출 없이 목록만 비운다
    list-param 조회 param 오버라이드. CRS 는 DOC_TYPE:'RP' + COMP_CD 가 필수 — 백엔드가 이 둘로 레거시 SKR_DOC_MST UNION 쿼리로 분기한다
    upload-param 업로드 추가 param(기본 FILE_EXPL/MNGT_NO/CORP_CD/CUST_CD/COMP_CD 에 병합)
    allowed-ext / upload-viewable-only 업로드 확장자 제한. 후자는 뷰어 허용목록(공통코드 FILE_EXT)과 같게 묶는다
    staging 선택/드롭한 파일을 서버로 보내지 않고 @files-added 로 넘긴다. 모아뒀다 일괄 전송하는 화면용
    can-upload / can-delete / readonly / viewer / auto-load / columns / title 노출·동작 제어
    이벤트 시점
    @uploaded 업로드 성공 후(목록 갱신은 컴포넌트가 이미 끝냄). 화면 후속 처리용
    @deleted 삭제 성공 후. 인자로 삭제된 행을 넘긴다
    @loaded 목록 조회 후
    @files-added staging 모드에서 파일이 선택/드롭됐을 때. 확장자 필터를 통과한 파일만 넘어온다

    스테이징 모드¶

    첨부 목록이 아니라 올리기 전 파일 목록을 다루는 화면(예: CrsFileUploadPopup 의 견적서 일괄 매칭 업로드)은 staging 으로 쓴다. 서버 조회·업로드·삭제를 끄고 드롭존·워터마크·확장자 검증·총건수만 재사용한다.

    <e-attach-file-grid
    ref="attachGrid"
    staging
    :auto-load="false"     <!-- 서버 조회 안 함 -->
    :can-delete="false"    <!-- 삭제 판단은 화면 몫 -->
    :columns="fileColumns"
    upload-viewable-only
    @files-added="fnAttachFiles"
>
    <template #actions>
        <e-grid-btn button-type="delete" @click.stop="fnDeleteRow"/>
    </template>
</e-attach-file-grid>

    행 조작은 this.$refs.attachGrid.getAdapter() 로 직접 한다. 총건수(:total)와 워터마크는 어댑터의 getRowCount() 를 읽는 반응형이라 화면이 행을 직접 넣어도 맞는다.

    뷰어 판정의 정본은 공통코드 TB_CMS_CD_DTL / MSTR_CD='FILE_EXT'(화이트리스트) 다. 컴포넌트가 /api/code/selectCommonCode 로 모듈 단위 1회만 조회해 공유한다. 허용목록 밖이면 MSG000400 경고, PDF 는 openPdfViewer, 나머지(이미지·ZIP)는 캐러셀 새 창(CmsImageCarouselPopup)으로 연다. 확장자를 늘리려면 코드가 아니라 공통코드를 고친다.

    ag-grid 렌더러/에디터¶

    src/components/manual/ag-grid/vue/ 에 그리드 셀용 렌더러·에디터가 있습니다 (AgCheckBoxRender, AgCodeBoxEditor, AgNumberBoxEditor, AgButtonRender 등). 그리드 컬럼 정의에서 이들을 지정해 셀 UI 를 구성합니다. ag-grid 는 25.3.0 으로 고정이며 이 버전의 cellRendererFramework API 가 유효합니다.
